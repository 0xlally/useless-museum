01 / IDEA & EXPERIENCE

产品越没用，体验越完整。

世界上已有许多解决真实痛点的工具。这个博物馆把注意力放在微不足道甚至不存在的问题：下午偷偷变长的影子、周一早上的哈欠、已经变冷却仍需要杯套的咖啡。

笑点来自严肃工艺与荒诞目的的反差。展品不是故意制作粗糙，而是在造型、材质、展签与试用流程上认真完成一个无用的使命。

一句荒唐需求 → 造型提示词 → Lux3D 生成
→ 三维展柜 → 叙事试用 → 无用认证与分享
预设展品原始需求试用反差
影子限长器怎么防止影子在下午偷偷变长？夹具锁紧，影子绕过去
哈欠收纳罐如何收纳周一早上的哈欠？罐子密封，人继续打哈欠
冷咖啡二次杯套给冷掉的咖啡再套一层杯套？更加稳定地冷着
灰尘队列整理机让桌上的灰尘排成队列？排好了，但桌子没干净
马上到等待计时器怎么量化朋友说的「马上到」？每条消息重置等待
周一暂停按钮让周一暂停五分钟？周一表示已读

用户可拖动旋转、缩放、看空间总览，并为展品选择三档无用程度。投票保存在当前设备，未设置虚构的全网热度。模拟试用和虚构评论均按艺术化叙事说明。

30 秒演示目标：认识一件发明 → 旋转模型 → 试用揭晓 → 投票 → 提出自己的问题。

02 / CORE CREATION PIPELINE

Lux3D 生成展品本体。

Lux3D 位于生成主流程：用户需求经服务端规则和造型模板转换为单件装置提示词，提交 G1 文生 3D 任务，再轮询真实任务状态、下载 GLB，加载到可旋转的三维展柜。需求转化目前为规则模板，不声明使用另一个大语言模型。

环节实现与证据
鉴权与创建服务端原始 Authorization 密钥；POST /lux3d/v1/generate/text-to-3d/task/create。凭据不发送给前端。
生成参数G1、photorealistic、100000 面、PBR、ZIP 与 GLB 输出。实际调用以审计记录为准。
异步任务真实官方 taskId 与本地 UUID 关联，6 秒查询一次；区分排队、处理中、成功、失败和取消。
缓存展示GLB 下载并验证文件头，落盘后通过本地模型路由供 Three.js 加载；临时官方 URL 不作为长期演示依赖。
过程追踪data/generations.json：任务与原始需求；data/audit.jsonl：创建、状态及缓存事件；data/models/：实际模型。

来源透明

最初六件程序化模型用于概念预览和稳定交互演示，明确标记为“概念装置”，不计为 Lux3D 生成成果。真实模型进入展柜后标记“Lux3D 生成”。卡片缩略图为示意插画。

稳定性与边界

已实现生成中限制重复提交、错误反馈、刷新恢复任务、本地持久化、GLB 缓存。首次生成需等待数分钟；评审可先浏览已生成馆藏。当前为受控本机 Demo，公开部署前应增加身份或额度控制。

首件生成过程

输入：影子在下午偷偷变长。造型：黄铜圆环、精密刻度、夹具、磨砂玻璃与圆形基座。目标是使“长度控制”这个荒唐意图能够由装置结构直观表达。

实际生成状态、缓存字节数、模型任务编号及截图见下一页的自动附录；不能把概念模型作为真实产物证据。
